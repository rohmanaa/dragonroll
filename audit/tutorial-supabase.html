Penting: config.example.js saat ini menunjuk ke proyek Supabase milik orang lain. Jangan menjalankan migrasi di sana tanpa izin pemiliknya. Buat proyek sendiri dengan langkah berikut.
1

Buat proyek

  1. Buka supabase.com, daftar (bisa pakai akun GitHub).
  2. New project: isi nama, password database (simpan baik-baik), pilih region terdekat, misalnya Singapore.
  3. Tunggu sekitar 2 menit sampai proyek siap.

Paket gratis cukup untuk pengembangan dan tes bersama teman. Proyek yang lama tidak aktif bisa dijeda otomatis, dan bisa dihidupkan lagi dari dashboard.

2

Aktifkan login

  • Authentication → Providers → Anonymous: aktifkan Allow anonymous sign-ins (dipakai room online).
  • Authentication → Providers → Email: aktif, dan Confirm email dimatikan. Login username dan password di game/assets/js/auth.js memetakan username ke email internal username@dragonroll-game.com, jadi tidak ada email yang dikirim.
3

Jalankan migrasi SQL

Buka SQL Editor → New query. Jalankan berurutan, satu file per query:

UrutanFileFungsi
1supabase/migrations/202611050001_multiplayer.sqlTabel game_rooms dan RPC room
2supabase/migrations/202611060001_game_events.sqlEvent log, profil publik, klaim reward

Salin isi file dari GitHub, tempel, lalu Run. Aman dijalankan ulang karena memakai if not exists dan create or replace. File ini hanya menambah dan tidak menghapus data yang ada.

4

Cek Realtime

Database → Publications → supabase_realtime: pastikan game_rooms dan game_events aktif. Kalau belum, aktifkan di sana.

5

Pasang URL dan kunci

  1. Project Settings → API: salin Project URL dan publishable/anon key.
  2. Ganti dua nilai itu di game/assets/js/multiplayer/config.example.js, lalu commit dan push.
Kunci anon memang boleh publik. Jangan pernah memakai kunci service_role di repo atau browser.
6

Buat akun uji

Untuk uji dua klien, siapkan dua akun. Aturan username: 3–16 karakter, hanya huruf, angka, atau underscore. Password minimal 6 karakter.

  • Lewat game: buka layar login/daftar, isi username dan password.
  • Lewat dashboard: Authentication → Users → Add user. Isi email username@dragonroll-game.com, isi password, centang Auto Confirm User.

Contoh pasangan akun: omanbogel dan omanbogel2.

Pakai password sederhana hanya di proyek uji yang bukan produksi, dan hapus akunnya setelah selesai. Password tidak ditulis di repo.
7

Query pengecekan

Tempel di SQL Editor setelah migrasi. Hasil yang benar: tabel=2, fungsi=4, realtime=1, kolom=1.

select
  (select count(*) from information_schema.tables where table_name in ('game_events','game_reward_claims')) as tabel,
  (select count(*) from information_schema.routines where routine_name in ('submit_game_action','set_game_public_profile','claim_game_reward','is_game_room_member')) as fungsi,
  (select count(*) from pg_publication_tables where pubname='supabase_realtime' and tablename='game_events') as realtime,
  (select count(*) from information_schema.columns where table_name='game_rooms' and column_name='event_seq') as kolom;

Kalau ada angka 0 atau migrasi error, catat pesan errornya untuk diperbaiki.

8

Keamanan

  • Cabut (revoke) setiap token GitHub yang pernah ditempel di chat. Pakai gh auth login atau Claude Code.
  • Anonymous Auth bisa disalahgunakan dalam jumlah besar. Atur rate limit atau CAPTCHA sebelum rilis publik.
  • Selama dadu diacak di klien, anggota room secara teknis bisa mengirim hasil dadu palsu. Ditutup di tahap server.
  • game_events tumbuh selama game, jadi pemangkasan atau snapshot checkpoint perlu direncanakan.
